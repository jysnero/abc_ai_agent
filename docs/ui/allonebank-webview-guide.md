# 올원뱅크 모바일 WebView 공통 UI 가이드 (임시)

이 문서는 AI Agent Platform이 생성하는 서비스 화면의 공통 기준이다. 코드 생성 시 `design/tokens.json`과 함께 Developer Agent 프롬프트에 그대로 전달된다.

- 대상: NH농협은행 올원뱅크 앱 안에서 실행되는 모바일 WebView
- 상태: **임시(provisional)**. 공식 NH 디자인 가이드, 컴포넌트, 전용 폰트, 로고, 캐릭터를 제공받지 않았다.
- 여기의 색상·크기 값은 첨부 참고 화면(ref-1~4)의 픽셀 샘플·추정값이거나 임시값이다. 공식 NH 규격이라고 표기하지 않는다.

## 1. 기준 우선순위

1. 명시적인 사용자 지시와 승인된 기획(request spec)
2. 제공된 공식 디자인 가이드·컴포넌트·브랜드 자료 (현재 없음)
3. 첨부 올원뱅크 참고 화면
4. 이 문서와 `design/tokens.json`의 임시값

자료끼리 충돌하면 임의로 덮어쓰지 않고 충돌 내용을 보고한다.

## 2. 앱 컨테이너와 WebView의 경계

| 영역 | 담당 | 생성 코드에서 |
|---|---|---|
| OS 상태바, 시스템 내비게이션 바 | OS | 만들지 않는다 |
| 앱 상단 헤더(화면 제목, 닫기 X, 홈·메뉴 아이콘) | 앱(네이티브) — **가정** | 만들지 않는다. 로컬 Preview에서는 템플릿의 "앱 컨테이너 모의" 영역이 대신한다 |
| 앱 하단 탭(홈/금융상품/내 자산/포인트쌓기/생활혜택) | 앱(네이티브) | 만들지 않는다 |
| 헤더 아래 본문, 서비스 내부 하단 고정 버튼, 바텀시트, 모달 | WebView | 생성한다 |

- 참고 화면에 있다는 이유만으로 OS 상태바나 앱 하단 탭을 웹페이지 안에 복제하지 않는다.
- 서비스 내부의 단계 이동(예: 목록 → 상세)은 WebView 안에서 처리한다. 앱의 뒤로가기·닫기와 연결하는 Native Bridge는 사용하지 않는다(현재 범위 밖).
- 경계가 불명확한 요소는 가정을 명시하고 사용자 확인을 받는다.

## 3. 참고 화면에서 확인한 패턴

| 패턴 | 참고 | 관찰 내용 |
|---|---|---|
| 목록 항목 | ref-1 | 좌측 일러스트 아이콘(약 56px), 굵은 제목 + 회색 보조 문구 2줄, 우측 보상 배지 |
| 보상 배지 | ref-1 | 연녹색 알약형 배경(`primary-soft`), 녹색 원형 P 아이콘(`point`), 녹색 문구 "최대 50" |
| 섹션 구성 | ref-1 | 연회색 페이지 배경(`bg-page`), 굵은 섹션 제목, 카드는 필요한 곳에만 사용 |
| 이벤트 시작 화면 | ref-4 | 따뜻한 베이지 배경(`bg-event`), 중앙 정렬 2줄 헤드라인, 보상 수치만 녹색 강조("10P"), 큰 일러스트, 우상단 텍스트 링크("안내"), 하단 전체 폭 주요 버튼 |
| 진행 화면 | ref-2 | 지시 문구 2줄 + 회색 보조 문구, 큰 녹색 숫자, 단계 표시(트랙 위 점, 활성 점 민트색) + "1 단계" |
| 보상 바텀시트 | ref-3 | 딤 배경, 상단 둥근 흰색 시트, 우상단 회색 닫기 X, 좌측 정렬 2줄 제목(수치 녹색 강조), 우측 코인 일러스트, 버튼 위 말풍선 안내, 전체 폭 주요 버튼 |
| 주요 버튼 | ref-3,4 | 진한 녹색(`primary`) 채움, 흰색 굵은 문구, 작은 모서리, 높이 약 52px, 좌우 여백 약 24px |

참고 화면의 광고 연계 문구("광고보고 시작하기", "버튼을 누르면 광고 화면으로 이동해요")는 해당 서비스의 기획이다. 승인된 기획에 광고가 없으면 가져오지 않는다.

녹색을 넣었다고 올원뱅크 스타일이 되지 않는다. 타이포그래피 위계, 여백, 버튼, 카드, 바텀시트, 정보 배치를 함께 맞춘다.

## 4. 시각 기준

- 금융 앱답게 명확하고 안정적인 구성. 화면마다 주요 행동 버튼은 하나.
- 제목·본문·보조 문구의 위계를 크기·굵기·색으로 구분한다(`typography.scale`).
- 좌우 여백 `space.gutter`, 정렬선 일관 유지. 카드·그림자는 역할이 있는 곳에만.
- 이벤트·게임 화면은 일러스트와 재미 요소를 허용하되 조작과 정보 전달을 가리지 않는다.
- 공식 로고·캐릭터·전용 폰트는 제공된 자료만 사용한다. 없으면 이모지가 아닌 단순 도형·임시 일러스트를 쓰고 "임시 자산"임을 결과 보고에 적는다.

## 5. 문구와 숫자 표기

- 한국어 중심, 해요체("받았어요", "예측해 주세요"). 자연스러운 줄바꿈(`word-break: keep-all`).
- 금액: `12,300원` (천 단위 쉼표, 단위 붙여 씀)
- 등락률: `+1.23%` / `-0.87%` (부호 표시, 소수 둘째 자리)
- 포인트: `10P`, 리워드: 기획에 적힌 명칭 그대로(예: 올원캔디)
- 날짜·시각: `5월 12일(월) 15:30`
- 상승/하락은 색(`rise`/`fall`)만으로 구분하지 않고 "상승"/"하락" 문구나 ▲/▼ 기호를 함께 표시한다.

## 6. WebView 레이아웃과 동작

- 모바일 우선. 320px, 360px, 390px, 430px 폭에서 가로 넘침·버튼 잘림이 없어야 한다.
- 큰 화면에서는 본문을 `space.content-max` 폭으로 중앙 배치한다.
- 긴 문구와 큰 글자 설정에서도 겹치지 않도록 고정 높이 대신 내용에 맞춰 늘어나게 한다.
- 터치 영역은 최소 44×44 CSS px(임시 기준).
- 하단 고정 버튼은 본문 끝에 같은 높이의 여백을 두어 본문을 가리지 않는다.
- safe area: 앱 컨테이너가 이미 처리한다고 가정하고 `env(safe-area-inset-bottom)`은 하단 고정 버튼에만 더한다(중복 여백 방지). 이 가정은 실제 앱에서 확인이 필요하다.
- 확대/축소를 막지 않는다(`user-scalable=no`, `maximum-scale=1` 금지).

## 7. 접근성 최소 기준

- 모든 버튼·링크에 접근 가능한 이름. 아이콘 전용 버튼은 `aria-label`.
- 키보드 포커스가 보이도록 유지(`focus-visible`).
- 상태(선택됨, 적중/미적중, 오류)는 색 외에 문구·아이콘으로도 표시.
- 바텀시트·모달은 열릴 때 포커스를 안으로 옮기고 닫기 버튼과 Esc로 닫는다.
- 이 기준을 점검했다고 접근성 전체 준수를 선언하지 않는다.

## 8. 생성 코드에서 토큰 사용

로컬 Preview 템플릿(`templates/browser_component/demo/index.html`)은 `design/tokens.json`을 CSS 변수와 Tailwind 테마로 변환해 넣는다. 생성 코드는 임의의 hex 값 대신 아래 클래스를 사용한다.

- 색: `bg-primary`, `text-primary`, `bg-primary-soft`, `text-point`, `bg-bg-page`, `bg-bg-event`, `bg-surface`, `bg-track`, `text-text-strong`, `text-text-body`, `text-text-sub`, `border-border`, `text-rise`, `text-fall`, `text-danger`, `bg-accent-mint`
- 모서리: `rounded-button`, `rounded-card`, `rounded-sheet`, `rounded-pill`
- 글꼴: 기본 `font-sans`(토큰의 시스템 폰트 스택)

## 9. 로컬 Preview 전용 요소

템플릿의 "앱 컨테이너 모의" 헤더와 화면 폭 전환 도구는 Preview 전용이다. 실제 서비스 콘텐츠(`#root`)와 분리되어 있으며 생성 코드가 의존해서는 안 된다.
